# Plumma

> Plumma SRL is an Italian software house in Modena that operates Plumma Connect, an
> aggregation gateway over mobile network operator intelligence. It sells enterprises one
> integration point for the operator-held identity, SIM and network-state signals exposed
> through the GSMA Open Gateway programme, instead of onboarding operator-by-operator and
> country-by-country. Plumma is a GSMA Open Gateway channel partner.

## What is unusual about this API

Plumma Connect is deliberately not shaped like CAMARA. Where the CAMARA family publishes one
endpoint per capability, Plumma Connect publishes a SINGLE OpenAPI 3.1 operation —
`POST /api` on `https://connect.plumma.it/services` — taking an E.164 phone number plus a
`commands` array. The CAMARA surface is an implementation detail behind that abstraction
rather than the developer contract. The command vocabulary, not the URL space, is the API.

Three things an agent must know before calling it:

1. **HTTP 200 does not mean success.** Every authenticated call returns 200; the real outcome
   is the numeric `status` inside the body (0 OK, 1 invalid number, 2 no coverage,
   4 partial reply, 5 unknown error), plus a per-command breakdown appended to
   `status_message` and a packed `cmd_enc` bitfield.
2. **Billing is per command an operator served, not per API call**, drawn from a prepaid Euro
   wallet. Status 0 and 4 are billable; 1, 2 and an empty 5 are not. Five commands are
   *global* and are billed for every country regardless of coverage.
3. **There is no idempotency key and no rate-limit header.** A retry of a served call is a
   second charge, and remaining budget is not observable at runtime.

## APIs

- [Plumma CONNECT API](https://connect.plumma.it/plumma-connect-docs/): one operation,
  `connectApi`, over 17 enumerated commands — SIM swap, KYC match, age verification, carrier
  and porting intelligence, roaming, digital footprint, call-divert detection and more.
  Base URL `https://connect.plumma.it/services`.

## What Plumma does not publish

No SDKs in any registry (the Technical Guide says the section is "under construction"), no
public Postman or Insomnia collection (the guide ships the literal placeholder "LINK_HERE"),
no GitHub organization, no MCP server, no A2A agent card, no `/.well-known/` documents, no
webhooks or AsyncAPI ("Webhooks and asynchronous notifications: This section is under
construction"), no changelog, no deprecation policy, and no per-command unit prices outside
the authenticated console.
